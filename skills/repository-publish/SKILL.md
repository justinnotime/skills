# Transactional repository publication

Use this package's `scripts/publish`, or the installed `repository-publish`
command. It includes the writer isolation, locking, Git publication, progress
staging and LFS download verification implementation. It needs Python 3.10 or
newer and Git; repositories containing LFS pointers also need Git LFS.

The bundled `scripts/publish worktree` commands also prepare and inspect
persistent task worktrees, commit selected outputs through private policy,
preserve unpublished branches after directory loss,
and run explicit validators in temporary historical checkouts. See the
[command contract](references/commands.md) before selecting those operations.

A native `--config` job can declare ordered command steps or file copies.
Use `--doctor` for local inspection and `--steps` for an explicit configured
selection. Keep failure policy and source selection in private configuration;
see the [configured job contract](references/commands.md#native-configured-jobs).

The caller selects the repository, remote branch, writer command, owned paths
and private state directory. Keep credentials, account selection and repository
rules in private configuration. Existing authorization for the scheduled writer
covers its normal publication; an inspection alone does not authorize a new
writer or a push. Read [the command contract](references/commands.md) when
configuring a writer or adapting an existing scheduled entry.

The writer receives a fresh worktree and a staging copy of its previous progress.
It must not create Git commits. Tracked changes outside its owned paths abort
the run. Untracked files outside those paths are discarded with the temporary
worktree. Writer failure, validation failure, rebase conflicts, rejected pushes
and failed LFS downloads do not advance durable progress. A failed reproducible
transaction is regenerated by the next run; do not treat its temporary checkout
as a retained hand-edited draft.

After a successful push, the package forces a fresh download of newly referenced
LFS objects with Git LFS's hash verification. One repair upload and another
download are attempted when needed. A small private pending-publication record
allows the next run to finish that verification after interruption before it
advances progress. A Git push returning zero alone is not a complete result.

Use explicit validation and message-command argument arrays for repository
policy. They run without shell interpolation and receive the selected worktree.
Validation runs again after each rebase, and the message command can refresh
metadata derived from the rebased rules. These commands are trusted code, not
instructions extracted from documents or incoming messages.

Report whether content was pushed, whether progress advanced, and any remaining
failure. Task-lock contention is a successful skip; it does not mean a new run
completed. A no-content run may legitimately advance progress past filtered
source records. The package does not install schedules or create credentials.

Development: `uv run --locked pytest tests -q` and `uv run --locked ruff check .`.
Tests use temporary repositories, synthetic writers and local bare remotes.
